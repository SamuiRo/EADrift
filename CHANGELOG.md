# Changelog

Причини й контекст кожного рішення — у [docs/HISTORY.md](./docs/HISTORY.md).

## 1.6.0

- `/export` — копія бази даних файлом у Telegram, знята через `VACUUM INTO`
  без зупинки бота.
- `exportDatabase()` у `database.js`.
- Документація: `DATA_COLLECTION.md`, `HISTORY.md`, цей changelog.

## 1.5.0

- Ліміт капіталу `CAPITAL_CAP_USDT` (типово 1000): усе рахується від
  `min(баланс, межа)`.
- Маржинальні слоти `MAX_OPEN_POSITIONS` (типово 3): плече підбирається під слот.
- Відмова при ліквідації ближчій за 2× відстань до SL.
- Ліміт одночасних позицій і захист від повторного сигналу на той самий символ.
- `STARTUP_TRADING_MODE`: режим переживає рестарт процесу.
- Протухла сесія Telegram більше не вішає процес без терміналу.
- `npm run auth`, `ecosystem.config.cjs`, `docs/DEPLOYMENT.md`.
- Обробка `unhandledRejection` / `uncaughtException`.
- `.env.example` з явними плейсхолдерами.

## 1.4.0

- Виправлено всі raw-SQL звіти в `analytics.js` (snake_case → фактичні camelCase-колонки).
- Нові звіти: `sourceStats`, `evaluationFunnel`, `rejectionReasons`.
- `npm run report`, Telegram-команда `/stats`.
- `EADRIFT_DB_PATH` для роботи з іншим файлом БД.
- Виправлено падіння ініціалізації на порожній базі.

## 1.3.0

- Режим `SHADOW`: повний конвеєр без ордерів.
- Таблиця `signal_evaluations` — знімок кожного рішення, включно з відмовами.
- `npm run replay` — офлайн-перевірка політик виходу.

## 1.2.0

- Зона входу визначається за значенням (канал пише `LOW - HIGH`).
- `signalGeometry.js`: перевірка геометрії сигналу і звірка чисел із текстом.
- Виправлено роздування позиції при плечі нижче 1x.
- Зважений R:R замість порогу до TP1.
- Власний SL від фактичної ціни входу з ATR-підлогою.
- Вхід по ринку; сітка TP 40/40/20.
- Нормалізація таймфрейму (`30` → `30m`).
- Поле `signals.source`, ідемпотентні міграції колонок.
