# Документація EADrift

Ця папка описує фактичну реалізацію проєкту станом на 10 червня 2026 року. Джерелом істини є код у `src/`; документація пояснює його структуру, поведінку та поточні обмеження.

## З чого почати

1. [ARCHITECTURE.md](./ARCHITECTURE.md) — компоненти, залежності та структура репозиторію.
2. [FLOWS.md](./FLOWS.md) — запуск, обробка сигналу, виконання угоди, моніторинг і відновлення.
3. [TRADING_STRATEGY.md](./TRADING_STRATEGY.md) — правила входу, risk engine, формули та керування позицією.
4. [DATA_MODEL.md](./DATA_MODEL.md) — SQLite/Sequelize, таблиці, статуси, події та аналітика.
5. [OPERATIONS.md](./OPERATIONS.md) — конфігурація, запуск, Telegram-команди та експлуатація.
6. [KNOWN_LIMITATIONS.md](./KNOWN_LIMITATIONS.md) — відомі ризики, технічний борг і напрямки розвитку.

## Коротко про систему

EADrift — однопроцесний Node.js ESM бот для Binance USD-M Futures. Він:

- читає сигнали з Telegram-каналу через MTProto (`gramjs`);
- парсить форматований текст сигналу;
- перевіряє актуальність входу та розраховує розмір позиції від ризику;
- виконує угоду автоматично або після підтвердження адміністратора;
- виставляє entry, SL і TP-ордери через Binance Futures REST API;
- відстежує позиції polling-монітором;
- зберігає сигнали, угоди, події та історію SL у SQLite.

## Джерела конфігурації

- Кодова конфігурація ризику: `src/core/riskEngine.js`.
- Змінні середовища: `src/config/app.config.js`.
- Інтервал моніторингу: `MONITOR_INTERVAL_MS`, типовий `5000` мс.
- Поточний торговий режим зберігається лише в пам'яті та після рестарту стає `CONFIRM_ONLY`.
